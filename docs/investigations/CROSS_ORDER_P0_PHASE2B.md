## Native Save ownership

In pinned Frappe v16.17.5, a Data control debounces its native `input` handler and reads `$input` when the handler executes. The same Form and controls are reused on route changes. The previous custom `controlValue` read an old `$input` (or `get_value`) during `before_save` and copied it into the new document. The underlying risk also affects dimensions and measurement controls, not only color.

At an actual DocumentContext generation transition, native scalar controls are reconciled synchronously to the new model. The native input/change event is tagged during DOM capture, before Frappe's handler, and `parse_validate_and_set_in_model` rejects a delayed event from an obsolete generation. Board text and dimensions accept custom projection only when a user input/change event was tagged with the current document token and the same DOM element/value. The `before_save` projection rechecks its token before and after its await; same-document unsaved input remains authoritative. Frappe v16's `frm.set_value({...})` schedules one field at a time and rereads mutable `frm.doc.name` on each task. The projection now calls native `frappe.model.set_value(capturedDoc, updates)`, which captures the original document once and applies all fields before asynchronous triggers. The legacy source contract was strengthened to assert this captured-document form of native model update; no Phase 1 RED assertion changed. The fast measurement shell carries order and generation attributes, and its row synchronization rejects a shell from an earlier visit. This uses native `frm.save()` / `savedocs`; no parallel save endpoint or permission bypass was introduced.

## Atomic print contract

The PlanTabs print action now passes its selected source tab and Plan row to the renderer. The renderer captures the DocumentContext token, order name, Plan row name and revision, canonical row geometry, current print permission, and a deep copy of the order's printable data. It requires a ready Plan Workspace whose server payload belongs to the same order; a supplied plan must match the selected row's geometry, and the Plan row board description must agree with the Order. It builds geometry from that verified row instead of reusing a visible DOM plan. After the asynchronous factory identity lookup, it revalidates visit generation, order, permission, row identity, revision, geometry and the captured printable document fields; a mismatch closes the pending window without emitting final HTML. Printed metadata contains the plan name and revision. Existing page layout, RTL, edge drawing, extra legend, and OFFCUT presentation remain in the renderer.

This contract intentionally fails closed when no owned Plan Workspace row is available. A direct renderer test was updated to supply a trusted row rather than bypass that boundary; its drawing and final print assertions remain intact.

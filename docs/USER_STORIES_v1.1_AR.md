> **قاعدة حاكمة:** وجود ملفات أو حقول تاريخية للمخزون لا يجعلها متطلبات حالية. النطاق الفعال يعتمد وصف اللوح النصي وأبعاده، ويستبعد المخزون والمستودعات والحجز والاستهلاك وStock Entry وبقايا الألواح.

---

## 2. رؤية المنتج

إدارة طلب درف MDF من لحظة تسجيل طلب الزبون حتى التسليم، مع إدخال سريع للقياسات، دعم الدرف العادية والمقصوصة والخاصة، حساب القشاط والمقاسات الخام، تحسين توزيع القطع على الألواح، تثبيت خطة قص معتمدة، حساب تكلفة الطلب وسعر الزبون، طباعة المستندات التشغيلية والفاتورة، وتمرير الطلب بين أقسام المعمل مع تسجيل الأخطاء والقطع التعويضية.

---

## 4. تعريف الأولوية

- **Must:** لازم للإصدار الحالي ولا ينجح التشغيل بدونه.
- **Should:** مهم جدًا، ويمكن تأجيله مؤقتًا دون كسر المسار الأساسي.
- **Could:** تحسين ذو قيمة، لكنه ليس شرطًا للإطلاق الأول.

---

## 5. قواعد قبول عامة

تطبق القواعد التالية على جميع القصص:

1. الحسابات والصلاحيات والحالات الحساسة تُفرض على الخادم، ولا تكون JavaScript مصدر الحقيقة.
2. الواجهة عربية أولًا وRTL، مع إبقاء الأرقام والمقاسات LTR عند الحاجة.
3. الصفر الصريح قيمة صحيحة في حقول التكلفة ولا يُستبدل بقيمة افتراضية.
4. الخطة المعتمدة والمراجعات السابقة غير قابلة للتغيير التاريخي.
5. المعاينة والحفظ العادي لا ينشئان مراحل إنتاج أو حركات مخزون أو آثارًا جانبية.
6. رسائل الخطأ تحدد السطر أو الحقل والمشكلة وطريقة التصحيح.
7. العمليات الحساسة تحفظ المستخدم والتاريخ وسجل الحدث.
8. لا تُستخدم وظائف المخزون المستبعدة لإيقاف إنشاء الطلب أو اعتماده أو إنتاجه أو طباعته.

# EPIC-01 — الوصول ومساحة العمل والصلاحيات

**الهدف:** عرض واجهة مناسبة لكل دور مع منع الوصول غير المصرح به على مستوى الخادم.

### US-ACC-001 — فتح تطبيق إدارة المعمل

**بصفتي** مستخدمًا مخولًا، **أريد** فتح تطبيق إدارة المعمل من شاشة التطبيقات، **لكي** أصل إلى عملي مباشرة.

**معايير القبول:**
- يظهر التطبيق باسم عربي مناسب وشعار المعمل.
- يفتح مساحة عمل Almdina ERP.
- لا يظهر للمستخدم غير المخول.

**الأولوية:** Must

### US-ACC-002 — واجهة مسؤول إدخال الطلبات

**بصفتي** مسؤول إدخال طلبات، **أريد** رؤية تطبيق المدينة والوحدات اللازمة فقط، **لكي** لا أتشتت بوحدات ERPNext غير المستخدمة.

**معايير القبول:**
- تكون مساحة Almdina ERP هي الافتراضية.
- تبقى وظائف اختيار الزبون والإعدادات الضرورية متاحة.
- تُخفى التطبيقات والمساحات غير المطلوبة.

**الأولوية:** Must

### US-ACC-003 — واجهة عامل الإنتاج

**بصفتي** عامل إنتاج، **أريد** الدخول مباشرة إلى صندوق مهامي، **لكي** أبدأ العمل بسرعة.

**معايير القبول:**
- تكون صالة الإنتاج الصفحة الرئيسية.
- لا تظهر قوائم الإدارة والتكلفة.
- تظهر الأوامر التي تخص مرحلته فقط.

**الأولوية:** Must

### US-ACC-004 — رؤية الطلبات المسندة فقط

**بصفتي** عامل إنتاج، **أريد** رؤية الطلبات والخطط المسندة إلي فقط، **لكي** لا أصل إلى أعمال عمال آخرين.

**معايير القبول:**
- تُطبق شروط الاستعلام على الطلب والخطة والمرحلة.
- لا يتجاوز الاستدعاء المباشر القيد.
- يرى المدير السجلات وفق صلاحياته الإدارية.

**الأولوية:** Must

### US-ACC-005 — فصل التكلفة عن التنفيذ

**بصفتي** مديرًا، **أريد** فصل صلاحية التكاليف عن صلاحية التنفيذ، **لكي** لا يطلع العامل على معلومات مالية لا تخصه.

**معايير القبول:**
- تكون حقول التكلفة في مستوى صلاحية أعلى.
- أدوار التشغيل لا ترى تبويب التكلفة أو القيم المالية.
- الأدوار المالية والإدارية المخولة تراها.

**الأولوية:** Must

### US-ACC-006 — حماية العمليات الحساسة

**بصفتي** مدير نظام، **أريد** فحص صلاحية كل عملية حساسة على الخادم، **لكي** لا يمكن تجاوز الحماية بتعديل الواجهة أو استدعاء API يدويًا.

**معايير القبول:**
- الاعتماد والتسعير والتوزيع وDXF والإرجاع والتسليم تتحقق من الدور والحالة.
- يعاد خطأ صلاحية واضح عند المنع.
- تُسجل العملية الحساسة عند نجاحها.

**الأولوية:** Must

# EPIC-02 — العميل وإنشاء الطلب وبيانات اللوح

**الهدف:** إنشاء طلب واضح يعتمد وصف اللوح النصي وأبعاده دون اعتماد على المخزون.

### US-ORD-001 — إنشاء طلب لزبون

**بصفتي** مسؤول إدخال طلبات، **أريد** إنشاء طلب مرتبط بزبون، **لكي** يمكن تتبع العمل والفاتورة.

**معايير القبول:**
- الزبون إلزامي.
- يمكن البحث بالاسم أو المعرّف.
- يظهر الزبون في القائمة والطباعة والتقارير.

**الأولوية:** Must

### US-ORD-002 — تاريخ الطلب

**بصفتي** مسؤول إدخال طلبات، **أريد** تعبئة تاريخ الطلب تلقائيًا مع إمكانية تعديله، **لكي** أوثق تاريخ الاستلام الصحيح.

**معايير القبول:**
- القيمة الافتراضية هي تاريخ اليوم.
- يقبل تاريخًا صالحًا.
- يظهر في المستندات والتقارير.

**الأولوية:** Must

### US-ORD-003 — المرجع الخارجي والملاحظات

**بصفتي** مسؤول إدخال طلبات، **أريد** تسجيل مرجع خارجي وملاحظات عامة، **لكي** أربط الطلب بورقة أو اتفاق سابق.

**معايير القبول:**
- الحقلان اختياريان.
- يحفظان دون التأثير على الحساب.
- تظهر الملاحظات في المواضع التشغيلية المناسبة.

**الأولوية:** Should

### US-ORD-004 — وصف اللوح كنص حر

**بصفتي** مسؤول إدخال طلبات، **أريد** كتابة وصف اللوح كنص حر، **لكي** أسجل النوع والسماكة واللون بصيغة يفهمها المعمل.

**معايير القبول:**
- الوصف إلزامي ويقبل العربية والإنجليزية.
- لا يتطلب ERPNext Item أو Warehouse.
- ينتقل الوصف إلى الخطة والتعويض والطباعة والتقارير.

**الأولوية:** Must

### US-ORD-005 — أبعاد اللوح الافتراضية

**بصفتي** مسؤول إدخال طلبات، **أريد** طولًا افتراضيًا 244 سم وعرضًا 122 سم، **لكي** أسرع إدخال المقاس الشائع.

**معايير القبول:**
- تطبق القيم عند غياب الإدخال فقط.
- يمكن تعديلها لكل طلب.
- تُحول إلى millimeter في الخطة وDXF.

**الأولوية:** Must

### US-ORD-006 — التحقق من أبعاد اللوح

**بصفتي** مستخدمًا، **أريد** رفض أبعاد اللوح غير الصالحة، **لكي** لا تنتج خطة قص خاطئة.

**معايير القبول:**
- الطول والعرض موجبان ومنتهيان.
- يرفض 0 والسالب وNaN وInfinity.
- يمنع Trim الذي يلغي المساحة القابلة للقص.

**الأولوية:** Must

### US-ORD-007 — سعر اللوح وأجر القص

**بصفتي** مدير حسابات، **أريد** إدخال سعر اللوح وأجر القص لكل لوح، **لكي** أعكس اتفاق المعمل الحقيقي.

**معايير القبول:**
- القيم غير سالبة ومنتهية.
- الصفر الصريح يبقى صفرًا.
- لا تستبدل القيمة المدخلة بإعداد افتراضي عند الحفظ.

**الأولوية:** Must

### US-ORD-008 — عزل بيانات الطلب المفتوح

**بصفتي** مستخدمًا يتنقل بين الطلبات، **أريد** ظهور بيانات الطلب المفتوح فقط، **لكي** لا أعمل على بيانات طلب سابق مخزنة في الواجهة.

**معايير القبول:**
- تثبت هوية المستند قبل عمليات التحميل غير المتزامنة.
- لا تظهر قياسات أو خطة الطلب السابق.
- لا يحتاج المستخدم إلى تحديث الصفحة لتصحيح البيانات.

**الأولوية:** Must

# EPIC-03 — إدخال القياسات السريع وإدارة الصفوف

**الهدف:** إدخال عدد كبير من الدرف بسرعة وثبات باستخدام لوحة المفاتيح.

### US-MEA-001 — إضافة مجموعة قياسات

**بصفتي** مسؤول إدخال طلبات، **أريد** إضافة عرض وطول وكمية، **لكي** أسجل مجموعة درف متطابقة.

**معايير القبول:**
- العرض والطول أكبر من صفر.
- الكمية عدد صحيح موجب.
- تحدد رسالة الخطأ رقم السطر المخالف.

**الأولوية:** Must

### US-MEA-002 — ترقيم القطع والنسخ

**بصفتي** مسؤول إدخال طلبات، **أريد** ترقيم الصفوف ونسخ الكمية تلقائيًا، **لكي** يسهل التعرف عليها في الخطة والإنتاج.

**معايير القبول:**
- ترقم المجموعات 1، 2، 3...
- الكمية 3 تنتج Labels مثل 1.1 و1.2 و1.3.
- تبقى Labels مستقرة عند الحفظ غير المؤثر.

**الأولوية:** Must

### US-MEA-003 — السماح بالتدوير

**بصفتي** مسؤول إدخال طلبات، **أريد** تحديد السماح بالتدوير لكل صف، **لكي** يستخدمه المحسن عند السماح فقط.

**معايير القبول:**
- الإعداد مستقل لكل صف.
- لا تدور قطعة غير مسموح بها.
- يظهر الاتجاه الفعلي في الخطة والطباعة.

**الأولوية:** Must

### US-MEA-004 — ملاحظات المجموعة

**بصفتي** مسؤول إدخال طلبات، **أريد** إضافة ملاحظة لكل مجموعة، **لكي** تصل التعليمات الخاصة إلى أقسام المعمل.

**معايير القبول:**
- الملاحظة اختيارية.
- تحفظ مع السطر الصحيح.
- تظهر في جدول القياسات والواجهات المناسبة.

**الأولوية:** Should

### US-MEA-005 — إدخال بلوحة المفاتيح

**بصفتي** مدخل بيانات متكرر، **أريد** انتقالًا منطقيًا بـTab وEnter، **لكي** أدخل الطلب دون استخدام الفأرة باستمرار.

**معايير القبول:**
- ينتقل التركيز Width ثم Length ثم Quantity.
- يضيف Enter صفًا أو ينتقل للسطر التالي وفق موضعه.
- يعود التركيز إلى أول حقل مناسب دون ضغطتين.

**الأولوية:** Must

### US-MEA-006 — العمليات الجماعية

**بصفتي** مسؤول إدخال طلبات، **أريد** تحديد عدة صفوف وتطبيق أو حذف قيم جماعيًا، **لكي** أعدل الطلبات الكبيرة بسرعة.

**معايير القبول:**
- توجد أوامر تحديد الكل للحقول الملائمة.
- حذف المحدد يتطلب تأكيدًا.
- لا يتغير صف خارج النطاق المحدد.

**الأولوية:** Should

### US-MEA-007 — الجدول المضغوط والمحرر الموسع

**بصفتي** مستخدمًا، **أريد** جدولًا مضغوطًا قابلًا للتمرير ونافذة إدخال موسعة، **لكي** أرى عددًا أكبر من الصفوف.

**معايير القبول:**
- ارتفاع الصف مناسب للعمل المكتبي.
- يعمل التمرير الرأسي والأفقي.
- تتزامن قيم المحرر الموسع مع الطلب.

**الأولوية:** Should

### US-MEA-008 — ثبات الكتابة العربية

**بصفتي** مستخدمًا عربيًا، **أريد** ألا تضيع الأحرف أو الأرقام أثناء الكتابة، **لكي** أثق بعملية الإدخال.

**معايير القبول:**
- لا يعيد Refresh غير متزامن فوق الحقل النشط.
- يدعم الكتابة العربية وIME.
- تُهمل الاستجابات القديمة وتحفظ آخر قيمة فعلية.

**الأولوية:** Must

# EPIC-04 — أنواع الدرف والرسم الخاص

**الهدف:** دعم الدرفة العادية والزاوية المقصوصة والشكل الخاص بصورة قابلة للحساب والطباعة وDXF.

### US-SHP-001 — اختيار نوع القطعة

**بصفتي** مسؤول إدخال طلبات، **أريد** اختيار عادية أو زاوية مقصوصة أو خاصة، **لكي** يطبق النظام قواعد الشكل الصحيحة.

**معايير القبول:**
- تقبل القيم المعتمدة فقط.
- العادية لا تطلب بيانات شكل إضافية.
- يظهر النوع في القياسات والخطة.

**الأولوية:** Must

### US-SHP-002 — تعريف الزاوية المقصوصة

**بصفتي** مسؤول إدخال طلبات، **أريد** تحديد موضع وأبعاد الزاوية المقصوصة، **لكي** تُرسم الدرفة كما طلب الزبون.

**معايير القبول:**
- يدعم المواضع الأربعة.
- أبعاد القص موجبة وأصغر من أبعاد القطعة.
- يوفر قيمًا أولية منطقية عند عدم إدخالها.

**الأولوية:** Must

### US-SHP-003 — فتح محرر الدرفة الخاصة

**بصفتي** عامل رسم أو مدخل طلب، **أريد** فتح محرر الدرفة الخاصة من السطر، **لكي** أنشئ الرسم دون مغادرة الطلب.

**معايير القبول:**
- يفتح الزر السطر الصحيح.
- يعمل بعد التنقل بين طلبات مختلفة.
- لا يعتمد على Cache أو ترتيب تحميل قديم.

**الأولوية:** Must

### US-SHP-004 — رسم هندسة خاصة

**بصفتي** عامل رسم، **أريد** إنشاء وتحريك هندسة الدرفة الخاصة، **لكي** أمثل الشكل المطلوب بدقة.

**معايير القبول:**
- تحفظ النقاط والمسارات ضمن حدود القطعة.
- يدعم التحديد والتحريك والتكبير.
- يمنع الحفظ أو الاعتماد عند هندسة غير صالحة.

**الأولوية:** Must

### US-SHP-005 — إضافة ملاحظة داخل الرسم

**بصفتي** عامل رسم، **أريد** إضافة ملاحظة بالنقر على مكانها، **لكي** أضع التعليمات في الموضع المقصود.

**معايير القبول:**
- زر إضافة الملاحظة يفعّل وضع الإدراج.
- النقر يضع نصًا بلا خلفية.
- يمكن تحريك النص وتعديله.

**الأولوية:** Must

### US-SHP-006 — حجم خط الملاحظة

**بصفتي** عامل رسم، **أريد** التحكم بحجم خط الملاحظة، **لكي** تبقى مقروءة في الشاشة والطباعة.

**معايير القبول:**
- يوجد تحكم واضح بالحجم.
- تحفظ القيمة مع الرسم.
- تطبق القيمة في جميع المخرجات.

**الأولوية:** Should

# EPIC-08 — التكلفة وسعر الدرفة الخاصة وعرض الزبون

- لا ينشئ أو يقيّم مخزونًا.

**الأولوية:** Could

### US-ADM-006 — إعدادات القص الافتراضية

**بصفتي** مدير إنتاج، **أريد** ضبط Kerf وTrim وأجر القص وطريقة التحسين والمهلة، **لكي** تبدأ الطلبات بقيم المعمل.

**معايير القبول:**
- تطبق على الطلب الجديد عند غياب القيمة.
- الصفر الصريح يحترم.
- لا تغير طلبًا معتمدًا.

**الأولوية:** Must

### US-ADM-007 — إعدادات تسعير الشكل الخاص

**بصفتي** مدير حسابات، **أريد** ضبط رسوم التصميم وCNC والعمل اليدوي والهامش، **لكي** تكون التقديرات موحدة.

**معايير القبول:**
- القيم غير سالبة.
- تستخدم للتقدير فقط.
- السعر النهائي يحتاج اعتمادًا.

**الأولوية:** Should

### US-ADM-008 — إعدادات Routing وOverride

**بصفتي** مدير نظام، **أريد** ضبط Routing وسياسة تجاوز المراحل، **لكي** أتحكم بسلوك الإنتاج.

**معايير القبول:**
- يمكن اختيار Routing افتراضي.
- Override يحتاج إعدادًا وصلاحية ويسجل.
- استثناء Unplaced معلن ومقيد إن تم السماح به.

**الأولوية:** Should

# EPIC-15 — الجودة والأمان والأداء والترحيل

**الهدف:** ضمان منتج قابل للصيانة وآمن ومستقر على Frappe/ERPNext v16.

### US-NFR-001 — أداء الحفظ والتنقل

**بصفتي** مستخدمًا، **أريد** حفظًا وتنقلًا سريعًا، **لكي** لا تعيق الواجهة عمل المعمل.

**معايير القبول:**
- لا يعاد optimizer في Save العادي.
- لا تتكرر طلبات الرسم والحساب بلا داع.
- تقاس عينة واقعية وتوثق النتيجة.

**الأولوية:** Must

### US-NFR-002 — حالات التحميل والرسائل

**بصفتي** مستخدمًا، **أريد** حالات تحميل ونجاح وخطأ واضحة، **لكي** أعرف نتيجة العملية.

**معايير القبول:**
- تمنع النقرات المكررة في العمليات الحساسة.
- تحدد الرسالة السطر أو الحقل والحل.
- لا تبقى الواجهة مجمدة بعد الخطأ.

**الأولوية:** Must

### US-NFR-003 — Clean Architecture

**بصفتي** مالك المنتج، **أريد** فصل Domain وApplication وInfrastructure وUI، **لكي** يبقى الكود قابلًا للتطوير والاختبار.

**معايير القبول:**
- Domain لا يستورد Frappe.
- Application ينسق حالات الاستخدام عبر Ports.
- Infrastructure يطبق Frappe وUI لا يكرر المعادلات.

**الأولوية:** Must

### US-NFR-004 — اختبارات Regression

**بصفتي** مطورًا، **أريد** اختبارات لكل قاعدة حرجة، **لكي** لا تعود الأخطاء.

**معايير القبول:**
- تغطي الحساب والهندسة والمراجعات والصلاحيات وDXF والإدخال.
- كل إصلاح مهم يضيف اختبارًا.
- تفشل الاختبارات عند كسر العقد المتوقع.

**الأولوية:** Must

### US-NFR-005 — فحوص CI

**بصفتي** فريق تطوير، **أريد** CI يفحص JSON وPython وJavaScript والاختبارات، **لكي** لا يصل كود غير صالح إلى الفرع الرئيسي.

**معايير القبول:**
- تعمل الفحوص على Pull Request.
- تحفظ نتيجة واضحة لكل فحص.
- لا يعتبر وجود Workflow دليل نجاح دون فحص النتيجة الفعلية.

**الأولوية:** Must

### US-NFR-006 — تثبيت وترحيل قابل للتكرار

**بصفتي** مدير نظام، **أريد** تثبيت التطبيق وترحيله بصورة Idempotent، **لكي** أرقّي المواقع بأمان.

**معايير القبول:**
- ينجح install-app على Frappe/ERPNext v16.
- ينجح migrate مرتين.
- لا تتكرر الأدوار أو أنواع القشاط أو Routing.

**الأولوية:** Must

### US-NFR-007 — حماية البيانات التاريخية

**بصفتي** مدير نظام، **أريد** الاحتفاظ بالحقول القديمة مؤقتًا مع تعطيلها، **لكي** لا تنكسر المواقع القائمة.

**معايير القبول:**
- تبقى الحقول المخزنية مخفية.
- تكون سياسات المخزون والحجز والبقايا معطلة.
- لا يستخدمها كود المنتج الجديد.

**الأولوية:** Must

### US-NFR-008 — تثبيت حدود النطاق

**بصفتي** مالك المنتج، **أريد** ضمان عدم اعتماد v1.1 على المخزون، **لكي** لا تعطل وظائف غير مطلوبة الطلب والفاتورة.

**معايير القبول:**
- لا Item إلزامي لهوية اللوح.
- لا Warehouse أو Availability أو Reservation أو Stock Entry أو Remnant.
- تبقى التكلفة والتسعير والفاتورة داخل النطاق.

**الأولوية:** Must

### US-NFR-009 — الترجمة وRTL

**بصفتي** مستخدمًا عربيًا، **أريد** مصطلحات عربية موحدة، **لكي** يستخدم العمال النظام دون معرفة الإنجليزية.

**معايير القبول:**
- تترجم الحالات والأزرار والرسائل الأساسية.
- لا يعتمد الحل على استبدال DOM فقط.
- تختبر RTL وLTR في المتصفحات الفعلية.

**الأولوية:** Must

### US-NFR-010 — منع السباقات والتكرار

**بصفتي** مدير أمن، **أريد** منع العمليات المتزامنة المتعارضة، **لكي** لا تنشأ خطتان أو مراجعتان أو مراحل مكررة.

**معايير القبول:**
- تستخدم Locks أو Transactions عند الاعتماد والتفعيل والتوزيع.
- إعادة الطلب لا تنشئ نسخة ثانية بلا داع.
- تكون العملية المتكررة آمنة أو مرفوضة بوضوح.

**الأولوية:** Must

### US-NFR-011 — النسخ الاحتياطي والاسترجاع

**بصفتي** مدير نظام، **أريد** اختبار Backup وRestore، **لكي** أرقّي الموقع دون فقدان البيانات.

**معايير القبول:**
- تؤخذ نسخة قبل الترقية.
- تستعاد في بيئة اختبار.
- تتحقق الطلبات والخطط والمرفقات والمراجعات.

**الأولوية:** Must

### US-NFR-012 — بوابة Go-Live

**بصفتي** مالك المنتج، **أريد** بوابة قبول موثقة، **لكي** لا يعلن الإصدار جاهزًا قبل الاختبار الميداني.

**معايير القبول:**
- تنجح اختبارات Bench والصلاحيات والطباعة وDXF والمتصفح والأداء.
- يسجل Pass/Fail/Evidence/Tester/Date.
- لا يتحول الإصدار من `1.0.0-dev` إلى `1.0.0` قبل الإغلاق.

**الأولوية:** Must

## 6. سيناريوهات شاملة End-to-End

### SCN-01 — طلب عادي عبر الشريون

1. ينشئ مسؤول الإدخال طلبًا للزبون.
2. يكتب وصف اللوح ويثبت أبعاده وسعره.
3. يدخل القياسات والقشاط.
4. يحسب الخطة ويراجع عدد الألواح والهدر والتكلفة.
5. يرسل الطلب للمراجعة ويعتمده مدير الإنتاج.
6. يرسله إلى مسار Sharyoun ويعين عامل الشريون.
7. يبدأ العامل المرحلة وينهيها ويسلمها لعامل التقشيط.
8. ينهي عامل التقشيط ويصبح الطلب جاهزًا للتسليم.
9. يطبع المسؤول الفاتورة وجدول القياسات عند الحاجة.
10. يعلم المخول الطلب كمُسلّم.

### SCN-02 — درفة خاصة عبر الرسم وCNC

1. ينشئ مسؤول الإدخال صفًا من النوع Special.
2. يفتح عامل الرسم محرر الشكل ويرسم الهندسة ويضيف الملاحظات.
3. يحسب النظام التقدير الأولي للسعر الخاص.
4. تعتمد إدارة الحسابات السعر النهائي.
5. تحسب الخطة ويعتمد الطلب.
6. يرسل مدير الإنتاج الطلب إلى مسار Drawing.
7. يعيد عامل الرسم حساب الخطة أو يصدر ويرفع DXF مخصصًا.
8. يعتمد عامل الرسم DXF.
9. ينتقل الطلب إلى CNC ثم التقشيط ثم التسليم.

### SCN-03 — تعديل طلب معتمد

1. يفتح المستخدم طلبًا معتمدًا.
2. يمنع النظام التعديل المباشر.
3. ينشئ المستخدم Revision جديدة، مع سبب اختياري.
4. يعيد النظام ضبط الخطة وDXF وموافقات سعر الشكل الخاص.
5. يعدل المستخدم القياسات ويعيد الحساب.
6. يعتمد مدير الإنتاج المراجعة الجديدة.
7. تصبح القديمة Superseded والجديدة Current.
8. يمنع إرسال النسخة القديمة إلى الإنتاج.

### SCN-04 — خطأ معمل وتعويض

1. يسجل العامل Incident على Label محدد.
2. ينشئ مدير الإنتاج Replacement من القطعة الأصلية.
3. ينشئ النظام Mini Cutting Plan ويحسب الخسارة المخططة.
4. يعتمد المدير التعويض.
5. يبدأ العامل التعويض وينهيه.
6. يحدث النظام الخسارة الفعلية والتكلفة الفعلية للطلب.
7. لا تتغير فاتورة الزبون بسبب خطأ المعمل.
8. يسمح بإغلاق الطلب بعد إغلاق التعويضات الإلزامية.

### SCN-05 — فشل DXF

1. يرفع عامل الرسم ملفًا بامتداد غير صحيح أو هندسة متداخلة.
2. يرفض النظام الملف برسالة توضح السبب.
3. يبقى الطلب في مرحلة الرسم.
4. لا يسمح النظام بالتسليم إلى CNC.
5. يرفع العامل ملفًا صالحًا ويعتمده.
6. يسمح النظام بإنشاء مرحلة CNC.

## 7. خارج النطاق الصريح

لا تنشأ User Stories جديدة ضمن v1.1 للموضوعات التالية إلا بقرار نطاق جديد موثق:

- تعريف اللوح كصنف مخزني إلزامي.
- المستودعات وكميات Bin.
- التحقق من توفر المخزون.
- حجز الألواح أو القشاط.
- Material Reservation.
- Material Consumption Log.
- Stock Entry أو Stock Ledger.
- فروق الاستهلاك الفعلي.
- إدارة بقايا الألواح وحجزها وإعادة استخدامها.
- تقييم المخزون أو تكلفة البقايا.
- القيود المحاسبية والأستاذ العام.

**لا يعني ذلك إلغاء التكلفة أو التسعير:** تكلفة اللوح والقص والقشاط، سعر الدرفة الخاصة، عرض الزبون والفاتورة والطباعة متطلبات أساسية.

## 8. Definition of Ready

تكون القصة جاهزة للتطوير عندما:

1. تكون الشخصية والغاية واضحتين.
2. تكون معايير القبول قابلة للاختبار.
3. تكون الحقول والأدوار والحالات المتأثرة معروفة.
4. يُحسم إن كانت القصة تغير Snapshot أو Workflow أو صلاحية.
5. لا تتعارض مع حدود النطاق الحالية.
6. تتوفر عينات بيانات أو رسومات عند الحاجة.

---

## 9. Definition of Done

تعد القصة منجزة عندما:

1. نُفذت في الطبقة المعمارية الصحيحة.
2. فُرضت القواعد الحساسة على الخادم.
3. أضيف اختبار آلي مناسب واختبار Regression عند إصلاح خطأ.
4. نجحت فحوص JSON وPython وJavaScript والاختبارات.
5. اختبرت الصلاحيات بحسابات أدوار فعلية.
6. اختبرت الواجهة العربية وRTL وسلوك لوحة المفاتيح.
7. اختبرت الطباعة أو DXF فعليًا إذا كانت القصة تمسهما.
8. لم تُدخل اعتمادًا جديدًا على المخزون المستبعد.
9. لم تكسر الطلب أو الخطة أو التكلفة أو الفاتورة أو الإنتاج.
10. وُثقت أي Migration أو قرار توافق تاريخي.

# ADR-001 — فصل توثيق الدرفة الخاصة عن هندسة التصنيع

Status: Accepted
Date: 2026-08-20
Owner: Almdina ERP

## Context

المحرر الحالي يطلب من مدخل البيانات بناء محيط هندسي مغلق وصالح للتصنيع، ثم يحوّل الرسم مباشرة إلى `special_shape_geometry_json`. هذا يخلط بين مهمتين مختلفتين:

- توثيق سريع وواضح لطلب العميل يقوم به مدخل البيانات.
- إعداد هندسة دقيقة للتصنيع وCNC يقوم به مصمم مختص خارج النظام.

النتيجة أن محرر الرسم الحالي ثقيل على مدخل البيانات، ومع ذلك لا يغني عن برنامج CAD للمصمم.

## Decision

يصبح سطح «الدرفة الخاصة» محرر توثيق بصري عربي سهل الاستخدام، وليس محرر CAD. يدعم:

- رفع صورة، أو مسحها من سكانر Windows عبر جسر Almdina المحلي المقيد بـloopback، أو التقاطها بالكاميرا، مع التدوير والشفافية والقفل.
- الملاحظات النصية والقياسات التوضيحية.
- أشكال جاهزة قابلة للتعديل.
- قلم ذكي ينظف الضربات ويغلق الأطراف القريبة دون الادعاء بأنها هندسة تصنيع.
- عرض التوثيق من الطلب والطباعة ومساحة المصمم.

عقد التوثيق الجديد هو `almdina.special-shape-documentation`، الإصدار 1، ويُحفظ في `special_shape_drawing_json`. لا يقرأه التخطيط أو DXF ولا يُسقط منه أي polygon للتصنيع.

يبقى `special_shape_geometry_json` عقد التصنيع الدقيق القائم. تغييره يتم فقط من مسار تصنيع مستقل ومصرّح له، وليس من محرر التوثيق.

## Invariants preserved

- `special_shape_geometry_json` يبقى الإصدار 1 بوحدات السنتيمتر ومصدر الحقيقة للتخطيط وDXF.
- مدقق الهندسة الحالي وحدود اللوح والتقاطع والمساحة لا تتغير.
- صلاحيات `view_drawing_workspace` و`edit_special_drawing` تبقى سلطة الخادم.
- لا تُعرض حقول تكلفة أو أسعار داخل مساحة التوثيق.
- حفظ التوثيق لا يغيّر plan hash ولا `plan_needs_recalculation`.
- تغيير التوثيق وحده لا يلغي سعر الدرفة الخاصة الذي تمت مراجعته؛ إعادة التسعير مرتبطة بتغير نوع الدرفة أو أبعادها الإجمالية أو كميتها وفق العقد المالي الحالي.
- العربية وRTL واللمس ولوحة المفاتيح حالات مدعومة، مع مالك واحد للحالة وAPI واحد للمساحة.

## Alternatives considered

1. **تحسين محرر CAD الحالي:** مرفوض لأنه يبقي المهمة الخاطئة على مدخل البيانات ولا يلغي حاجة المصمم إلى CAD خارجي.
2. **الصورة فقط:** غير كافٍ لأن القياسات والملاحظات والأشكال الجاهزة تقلل سوء الفهم وتسهل الطباعة.
3. **استخدام ملف DXF كتقنية توثيق:** مرفوض لأنه يعيد خلط الوثيقة التوضيحية مع عقد التصنيع.

## Security/data implications

- صورة المرجع ملف خاص مرتبط بطلب ودرفة محددين، ولا يُقبل `file_url` عشوائي.
- كل قراءة ورفع ومسح ملف تعيد التحقق من صلاحية الوثيقة ونطاق الدرفة لمنع IDOR.
- امتدادات الصور وحجمها محدودة من الخادم، ولا تحفظ البيانات الثنائية داخل JSON.
- `special_shape_drawing_json` يخضع لمحدد حجم وعدد عناصر وقائمة أنواع مسموحة.
- لا تُضاف أسماء Roles إلى الواجهة أو الخدمة.
- جسر السكانر لا يملك صلاحية Frappe ولا يكتب JSON؛ الصورة الناتجة تمر دائمًا بخدمة الرفع الخاصة ونطاق الدرفة.

## Migration plan

1. اعتماد عقد التوثيق ومعايير القبول وتصميم الواجهة.
2. إضافة عقد الخادم الجديد ومحول قراءة آمن؛ الرسومات القديمة تظهر كتوثيق غير متاح ولا تتحول إلى تصنيع.
3. إضافة صورة المرجع والملاحظات والقياسات، ثم الأشكال والقلم الذكي.
4. ربط العرض بالطلب والطباعة وتسليم المصمم.
5. تحويل نقطة الدخول إلى المحرر الجديد.
6. حذف أصول ومحملات واختبارات V3/V4 القديمة بعد إثبات أن runtime لا يستدعيها.

لا توجد هجرة بيانات مطلوبة؛ قرر مالك المنتج أن الرسومات القديمة لا يلزم الحفاظ عليها بعد تنظيف قاعدة البيانات.

## Test plan

- Unit tests لعقد الوثيقة والتعقيم والقلم الذكي وsnap والأشكال.
- Service tests للصلاحيات وIDOR وحفظ التوثيق دون تعديل هندسة التصنيع أو plan hashes.
- Upload tests لنوع الملف والحجم والارتباط الخاص بالدرفة.
- Frontend contracts للـassets ونقطة الدخول وRTL والاختصارات والحالة غير المحفوظة.
- Print contract يثبت ظهور الصورة والملاحظات والقياسات وعدم ظهور التكلفة.
- UAT بمدخل بيانات حقيقي على لابتوب وجهاز لمس، ثم مراجعة المصمم للخرج المطبوع.

## Rollback

قبل حذف المحررات القديمة يمكن إعادة facade إلى V4 دون تغيير schema. بعد الحذف يكون rollback بإعادة ملفات V4 من Git فقط؛ `special_shape_geometry_json` لم يتغير طوال الانتقال.

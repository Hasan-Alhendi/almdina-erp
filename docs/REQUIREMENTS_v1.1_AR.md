## 2. الهدف من النظام

إدارة طلب قص الدرف من إدخال طلب الزبون حتى تسليمه، بما يشمل:

- وصف اللوح وأبعاده وتكلفته.
- إدخال قياسات الدرف وأعدادها وأشكالها.
- تحديد القشاط الافتراضي والاستثناءات لكل ضلع.
- حساب المقاسات الخام بعد خصم سماكة القشاط.
- تحسين توزيع القطع على الألواح.
- تثبيت خطة القص المعتمدة وتتبع نسخ الطلب.
- حساب تكلفة الطلب وسعر الزبون.
- إصدار فاتورة الزبون وجدول القياسات وخطة التنفيذ.
- تمرير الطلب بين مراحل الإنتاج.
- تسجيل أخطاء الإنتاج والقطع التعويضية وتكلفتها الداخلية.

## 3. حدود النطاق

### 3.1 داخل النطاق

1. طلبات قص الدرف وربطها بالزبون.
2. وصف اللوح كنص حر، وليس كصنف مخزني.
3. طول وعرض اللوح، بقيم افتراضية 244 × 122 سم.
4. الدرف العادية، والزاوية المقصوصة، والشكل الخاص.
5. القشاط الافتراضي والقشاط المخصص لكل ضلع.
6. تكلفة اللوح والقص والقشاط والشكل الخاص.
7. سعر الزبون والفاتورة والطباعة.
8. تحسين القص وحساب عدد الألواح والهدر.
9. خطط القص المعتمدة وغير القابلة للتعديل.
10. مسارا الإنتاج: الشريون، أو الرسم ثم CNC، ثم التقشيط والتسليم.
11. استيراد وتصدير DXF ضمن الصلاحيات المعتمدة.
12. أخطاء الإنتاج والقطع التعويضية والخسارة الداخلية.
13. التقارير التشغيلية وتقارير التكلفة.
14. الصلاحيات وسجل التغييرات.

### 3.2 خارج النطاق

المزايا التالية غير مطلوبة، ولا يجوز أن تمنع حفظ الطلب أو اعتماده أو بدء
الإنتاج أو إتمامه:

- تعريف اللوح كـ ERPNext Item.
- Warehouse وBin وكميات المخزون.
- التحقق من توفر المواد.
- حجز الألواح أو القشاط.
- Material Reservation.
- Material Consumption Log.
- Stock Entry أو Stock Ledger.
- تسجيل الاستهلاك الفعلي أو فروق الاستهلاك.
- إدارة بقايا الألواح أو حجزها أو إعادة استخدامها.
- تقييم المخزون أو تكلفة البقايا.
- محاسبة القيود أو الأستاذ العام أو الربحية المحاسبية.

استبعاد المحاسبة هنا لا يعني حذف التسعير. حساب تكلفة الطلب وسعر الزبون
وفاتورته جزء أساسي من المنتج.

| الدور | المسؤوليات |
|---|---|
| Order Entry | إنشاء الطلب وتعديل المسودة وإرسالها ومتابعتها |
| Production Manager | المراجعة والاعتماد والإسناد والإلغاء المنضبط واعتماد التعويض |
| Accounts Management | رؤية التكلفة واعتماد السعر الخاص للشكل الخاص |
| عامل رسم | تنفيذ مرحلة الرسم واعتماد DXF وفق المسار |
| عامل شريون | تنفيذ مرحلة الشريون |
| عامل CNC | تنفيذ مرحلة CNC |
| عامل تقشيط | تنفيذ مرحلة التقشيط |
| Cutting Operator / Edge Operator | أدوار توافقية للتشغيل الحالي |
| System Manager | الإعدادات التقنية وإدارة النظام |

قواعد الصلاحيات:

- لا يرى عامل الإنتاج حقول التكلفة ذات Permission Level 1.
- لا يعتمد الطلب إلا مدير الإنتاج أو مدير النظام.
- لا يعدّل الطلب المعتمد في مكانه؛ ينشئ Revision جديد.
- لا يعتمد السعر الخاص إلا صاحب صلاحية السعر.
- لا يبدأ العامل مرحلة غير مسندة إليه، إلا بصلاحية إدارية صريحة.
- صلاحيات المتصفح لا تكفي؛ يجب تنفيذ الحماية نفسها على الخادم.

## 5. نموذج البيانات

### 5.1 Door Cutting Order

يحتوي الطلب على الأقل على:

- رقم فريد، والزبون، وتاريخ الطلب، والحالة.
- رقم المراجعة وسلسلة المراجعات.
- وصف اللوح النصي وطوله وعرضه بالسنتيمتر.
- Kerf وTrim Margin بالملليمتر.
- طريقة التحسين ونوع ماكينة القص.
- سعر اللوح وتكلفة القص لكل لوح.
- القشاط الافتراضي ولونه.
- جدول الدرف.
- إجماليات المساحة والقشاط وعدد الألواح والهدر.
- تكلفة اللوح والقص والقشاط والإجمالي التشغيلي.
- إجمالي سعر الزبون وحالة التسعير.
- خطة القص الحالية والخطة المعتمدة.

### 5.2 Door Cutting Order Detail

يمثل كل سطر مجموعة درف متطابقة، ويحتوي على:

- رقم المجموعة.
- العرض والطول بالسنتيمتر.
- الكمية كعدد صحيح موجب.
- السماح بالتدوير.
- نوع القطعة: عادية، زاوية مقصوصة، أو خاصة.
- بيانات الشكل عند الحاجة.
- اختيار القشاط على الأضلاع الأربعة.
- نوع القشاط الأساسي.
- استثناء نوع القشاط لكل ضلع عند الحاجة فقط.
- المقاسات الخام المحسوبة.
- المساحة وأمتار القشاط وتكلفته.
- الملاحظات.

### 5.3 Cutting Plan

خطة القص المعتمدة Snapshot تاريخي، وتحتوي على:

- الطلب والمراجعة.
- نسخة المحرك والطريقة المستخدمة.
- أبعاد اللوح وKerf وTrim وقت الاعتماد.
- الألواح المطلوبة.
- القطع الموضوعة وإحداثياتها واتجاهها.
- المساحة المستخدمة والهدر.
- Snapshot التكلفة.
- نتيجة التحقق الهندسي.
- المستخدم والتاريخ عند الاعتماد.

### 5.4 Replacement Piece

القطعة التعويضية مرتبطة بالطلب والخطأ والقطعة الأصلية، وتحتوي على:

- وصف اللوح النصي نفسه.
- القياسات والقشاط المنسوخة من القطعة الأصلية.
- خطة قص مصغرة.
- حالة التنفيذ.
- الخسارة الداخلية المخططة والفعلية.
- المستخدمين والتواريخ.

لا تحتوي دورة التعويض الفعالة على مصدر مخزني أو Stock Entry أو بقايا.

## 6. دورة حياة الطلب

```text
Draft → Pending Review → Approved
Approved → At Sharyoun → At Sanding → Ready for Delivery → Delivered
```

```text
Rejected
On Hold
Cancelled
```

## 9. القشاط والمقاسات الخام

### 9.1 قاعدة النوع

- `default_edge_type` هو النوع الافتراضي للطلب.
- `row.edge_type` يغيّر النوع للقطعة كاملة عند اختياره.
- حقول Override لكل ضلع تستخدم فقط عند اختلاف ذلك الضلع.
- إذا لم يوجد اختلاف، لا تعرض الطباعة النوع الافتراضي داخل كل صف.

### 9.2 خصم السماكة

لكل ضلع سماكة فعالة مستقلة:

```text
Raw Width
= Finished Width - Left Edge Thickness - Right Edge Thickness

Raw Length
= Finished Length - Top Edge Thickness - Bottom Edge Thickness
```

يتم الخصم فقط للضلع المحدد للقشاط، ويجب منع أي نتيجة صفرية أو سالبة.

### 9.3 حساب القشاط

```text
Long Edge Meters
= Length CM × selected long sides × Quantity ÷ 100

Width Edge Meters
= Width CM × selected width sides × Quantity ÷ 100

Edge Cost
= Σ(side meters × effective side rate)
```

| ID | المتطلب | معيار القبول |
|---|---|---|
| FR-EDGE-001 | أسعار الأنواع من Edge Banding Type | لا توجد معادلة سعر مكررة في JavaScript |
| FR-EDGE-002 | كل ضلع يقبل نوعًا وسماكة مستقلين | أربعة أنواع مختلفة تعطي خصمًا وسعرًا صحيحين |
| FR-EDGE-003 | السعر Snapshot عند الاعتماد | تعديل Master لاحقًا لا يغير الطلب المعتمد |
| FR-EDGE-004 | لون القشاط يظهر في المستندات المناسبة | لا يخلط مع هوية اللوح |
| FR-EDGE-005 | الطباعة تعرض الاستثناءات فقط | الصف الافتراضي يبقى نظيفًا وقابلًا للقراءة |

## 11. حساب التكلفة وسعر الزبون

```text
Board Cost
= Required Boards × Board Rate USD

Cutting Cost
= Required Boards × Cutting Cost Per Board USD

Edge Cost
= Sum of effective edge side costs

Operational Order Cost
= Board Cost + Cutting Cost + Edge Cost

Customer Quote Total
= Operational Order Cost + Approved Special Shape Pricing
```

## 13. الطباعة

### 13.1 جدول القياسات

- A4 عمودي.
- عنوان ورقم الطلب والمراجعة والزبون.
- وصف اللوح ومقاسه ولون القشاط عند وجوده.
- عرض وطول وعدد ونوع القطعة والقشاط المخصص والملاحظات.
- رأس الجدول يتكرر في الصفحات.
- الصف لا ينقسم بين صفحتين.
- حجم خط قابل للقراءة، والهدف التقريبي 26 صفًا عاديًا في الصفحة.
- لا يعرض أسعارًا؛ هذا مستند تشغيل.

### 13.2 خطة القص

- تستخدم الخطة المعتمدة فقط في النسخة الرسمية.
- كل لوح في صفحة مستقلة عند الحاجة.
- الرسم يحافظ على نسبة الأبعاد.
- كل قطعة تعرض Label والمقاس.
- القشاط يظهر على الحواف الصحيحة بعد التدوير.
- تعرض Kerf وTrim والطريقة والمراجعة.
- لا تعرض صنف مخزون أو مادة/لون/سماكة مخزنية أو بقايا.

## 17. Clean Architecture وClean Code

اتجاه الاعتمادات:

```text
UI / Frappe hooks
        ↓
Infrastructure adapters
        ↓
Application use cases
        ↓
Domain rules
```

- `domain` لا يستورد Frappe أو ERPNext أو services.
- `application` ينسق حالات الاستخدام من خلال Ports.
- `infrastructure` يحتوي استعلامات Frappe والتحويل بين Documents وDomain.
- `services` القديمة تكون Facades رقيقة فقط عند الحاجة للتوافق.
- UI لا يكرر معادلات التكلفة أو قواعد الاعتماد.
- اسم الدالة يصف مسؤولية واحدة.
- لا توجد دالة تجمع SQL وحسابًا ورسم HTML في كتلة واحدة.
- لا تستخدم `or default` عندما يكون الصفر قيمة صريحة صحيحة.
- لا توجد قيم سعر مثبتة في JavaScript.
- لا توجد استدعاءات مخفية ذات Side Effects من Preview أو Start.
- الأخطاء المتوقعة لها رسائل عمل مفهومة.
- التوافق القديم موثق ومغطى باختبار ولا يستخدمه كود جديد.
- كل إصلاح خطأ مهم يضيف Regression Test.

### 20.1 الطلب والحساب
